# Payments Service — Agent Guide

## Architecture Overview

The payments service is a REST API built on Express.js and TypeScript. It handles charge creation, refund processing, and webhook events from Stripe. Data is persisted in PostgreSQL using both Knex (for migrations) and Sequelize (for models — yes, we know this is inconsistent, it's a known tech debt item from Q2 2023 when we merged two teams).

All Stripe webhooks go through `src/api/webhooks.ts`, which verifies the Stripe signature before processing. The verification key is in `STRIPE_WEBHOOK_SECRET`. Never log this value.

## Getting Started

Prerequisites: Node.js 24.x LTS, PostgreSQL 15+

1. `npm install`
2. `cp .env.example .env` and fill in the values
3. `scripts/bootstrap.sh`
4. `npm run dev`

## Testing

- Unit tests: `npm test`
- Integration tests: `npm run test:integration` (requires a running database)
- Coverage: `npm run test:coverage`

## Coding Conventions

- TypeScript strict mode; no `any` without a comment explaining why
- New database queries go through the ORM models, not raw SQL (except migrations)
- Create migrations only with `npx knex migrate:make <name>`; never edit an existing migration file
- Use `src/utils/logger.ts` for all logging; never `console.log`
- Throw `AppError` from `src/utils/errors.ts`
- Never commit `.env` files or secrets
- Never run `git push --force` on `main`

## API Documentation

Base URL: `/api/v1`. Bearer token in `Authorization`.

`POST /api/v1/charges` — Create a charge. Body: `{ "amount": 1000, "currency": "usd", "customerId": "cust_123", "paymentMethodId": "pm_456" }`. Response: 201.
`GET /api/v1/charges/:id` — Retrieve a charge. Response: 200.
`POST /api/v1/charges/:id/capture` — Capture an authorized charge. Response: 200.
`POST /api/v1/refunds` — Create a refund. Body: `{ "chargeId": "ch_123", "amount": 500 }`. Response: 201.
`POST /api/v1/webhooks/stripe` — Stripe webhook endpoint; `stripe-signature` header required.

## Deployment

Merging to `main` runs CI (`.github/workflows/`), builds a Docker image, pushes it to ECR, and redeploys the ECS service. Manual deployments: `docs/deployment.md`.
